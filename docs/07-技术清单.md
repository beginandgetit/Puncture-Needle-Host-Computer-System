> 避免出现"用了某个技术但说不清为什么"的情况。

## 1. 感知与通信层

| 技术 | 用来做什么 | 达到的效果 |
| --- | --- | --- |
| **BLE GATT 通知**（`0x55 0x61` 数据流） | 订阅 `ffe4` 特征值接收传感器数据 | 10 Hz 连续数据，无需轮询、功耗低 |
| **bleak + Windows WinRT** | 跨平台 Python BLE 客户端 | 不依赖厂商 SDK/驱动，直接接进产品 |
| **设备 profile 固化 UUID**（`ble.py`） | 写死 FFE5/FFE4/FFE9 | 不再"猜特征值"，换机器也不选错通道 |
| **扫描到的设备对象连接** | 优先用 `BLEDevice` 而非地址字符串 | 连接从 ~11 s 降到 ~5 s |
| **地址直连 + 名称重扫兜底** | 缓存地址失败时回退 | 地址变了也能连上，不要求用户改配置 |
| **指数退避自动重连** | 2 s 起 ×1.6，上限 15 s | 拔电、走远、干扰后自动恢复 |
| **设备缓存**（`%LOCALAPPDATA%\wt901-control`） | 记住上次成功地址 | 二次启动跳过扫描，快 3–6 s |
| **FF AA 命令帧**（`wit_frame`） | 构造寄存器写帧 | 为后续改速率/输出内容留接口，当前不自动写设备 |

## 2. 协议解析与数据质量层

| 技术 | 用来做什么 | 达到的效果 |
| --- | --- | --- |
| **增量式帧解析 + 逐字节重同步** | 处理 BLE 分片、粘包、前导垃圾 | 丢包/错位后自动恢复，不用重连 |
| **校验和（0x51/0x52/0x53 分帧）** | 识别误码帧 | 分帧模式下坏帧可被丢弃，不污染姿态 |
| **合并帧 / 分帧双格式支持** | `0x61`（20 B）与 `0x51-53`（11 B） | 固件换了输出格式也不用改代码 |
| **int16 小端 + 量程换算** | raw → g / °/s / ° | 输出工程单位，上层不用关心原始计数 |
| **缓冲区上限与丢弃统计** | 异常洪流时只保留尾部 | 不会因坏数据无限吃内存 |
| **坏帧/丢字节计数**（`bad_sum`/`bad_hdr`/`dropped`） | 实时暴露链路质量 | 联调时一眼看出是帧格式错还是误码 |
| **单调时钟 + 墙钟双时间戳** | `t_mono` 判超时，`t_wall` 落盘对时 | 系统改时间不影响超时逻辑 |
| **速率 / 抖动统计** | 1 s 窗口计算 Hz 与 P95 间隔 | 量化"这条链路到底稳不稳" |
| **最新值缓存（合并三帧）** | 把 0x51/0x52/0x53 合成一份状态 | 分帧模式下也能拿到同一时刻的完整姿态 |

## 3. 姿态与几何层

| 技术 | 用来做什么 | 达到的效果 |
| --- | --- | --- |
| **四元数（而非欧拉角）** | 内部统一用四元数运算 | 针竖直向下时（pitch=±90°）不出现万向锁 |
| **ZYX 欧拉角 → 四元数** | 兼容设备自带融合输出 | 直接用设备角度，零额外算法成本 |
| **相对参考姿态（R₀）** | 开机把当前姿态定为 0° | 不依赖磁北，手术室金属/电刀不影响 |
| **针轴标定 `s = Rᵀ·w`** | 竖直姿态反解针轴在传感器系的方向 | 安装方向任意，标一次即可；只依赖重力 |
| **2 自由度方向模型** | 只跟踪针的方向，不跟踪绕轴自转 | 圆柱针的自转无意义，少了 1 个误差源 |
| **指数平滑 + 球面插值** | 抑制 10 Hz 数据的抖动 | 界面看起来连贯，不抖 |
| **倾角分解（总/左右/前后）** | 把方向拆成两个正交角 | 接近垂直时也不跳变（方位角会跳） |
| **与计划方向夹角** | `acos(u·u_plan)` | 直接给出"偏了多少度"这个唯一决策量 |
| **针尖运动学 `p = p_entry + d·u`** | 预留：有深度即可算针尖 | 现在不用，但接口和测试已就位 |
| **两姿态旋转对齐（Kabsch 简化版）** | 传感器系 ↔ 世界系对齐 | 为后续多传感器/外部基准留基础 |

## 4. 界面与交互层

| 技术 | 用来做什么 | 达到的效果 |
| --- | --- | --- |
| **PySide6（Qt6, LGPL）** | 桌面 GUI 框架 | 可打包、可上工控机、许可证友好 |
| **QPainter 自绘 3D（无 OpenGL）** | 透视投影 + 针体/网格/坐标轴 | 不引入 VTK/OpenGL 依赖，部署简单 |
| **轨迹球旋转（绕屏幕轴）** | 拖动旋转观察 | 针与坐标系作为刚体一起转，不会"针被钉住" |
| **透视投影 + 深度排序** | 近大远小、遮挡关系 | 有空间感，方向判断直观 |
| **60 fps 定时器 + 插值** | 独立于 10 Hz 数据刷新 | 数据慢但界面不卡顿 |
| **状态机 UI（连接/重连/断流）** | 三种状态不同表现 | 用户永远知道"现在能不能信这个数" |
| **数据过期置灰 + NO DATA** | 0.4 s 无新数据即失效 | 绝不把旧姿态当新姿态显示（安全关键） |
| **X/Y/Z 轴标签 + 角度弧** | 可视化坐标系与偏差 | 一眼看清"偏到哪个方向" |
| **颜色阈值（2°/5°）** | 绿/橙/红 | 余光也能判断是否超限 |
| **CSV 记录 + 截图模式** | 数据落盘、界面留证 | 复盘、写报告、回归对比 |
| **离屏渲染（offscreen）** | 无显示器也能跑 GUI | CI/自动化测试可验证界面 |

## 5. 工程与交付层

| 技术 | 用来做什么 | 达到的效果 |
| --- | --- | --- |
| **src 布局 + pyproject（PEP 621）** | 标准 Python 包结构 | `pip install` 即可接入其它产品 |

| **黄金帧（golden frames）** | 固定输入 → 固定输出 | 协议解析一旦改坏立刻发现 |

| **文档体系（7 份）** | 需求/方案/联调/SDK/位姿/样机/参数 | 交接不用口头传 |

## 6. 可靠性与安全设计

| 设计 | 目的 | 效果 |
| --- | --- | --- |
| 断链立即置失效 | 不信任旧数据 | 界面变灰，不会"停在上一帧" |
| 数据超时（0.4 s） | 覆盖"连上了但不推流" | 静默故障也能被发现 |
| 自动重试不退出 | 占用/断电是常态 | 关闭上位机后无需重启程序 |
| 占用诊断提示 | BLE 单连接是硬限制 | 用户知道该关哪个软件 |
| 不自动写设备寄存器 | 避免写坏配置 | 参数修改必须人工确认 |
| 只读默认 + 显式开关 | 视角锁定、暂停数据 | 误操作不会改变测量结果 |

## 7. 明确**没有**采用的技术（边界）

| 技术 | 为什么不用 |
| --- | --- |
| 磁力计融合 | 手术室金属环境不可信；相对参考已够用 |
| 加速度二次积分求位置 | 误差随时间平方发散，10 s 可达几十厘米 |
| 光学/电磁跟踪 | 成本与体积高，当前只做角度引导 |
| 双 IMU 弯曲感知 | 刚性针不需要 |
| 卡尔曼滤波 | 当前无外部观测，EKF 无处融合；等有深度/光学再加入 |
| 深度学习 | 数据量与应用场景都不需要 |

---

## 8. 一句话总结

**用 BLE + 帧解析保证"数据能稳定拿到"，用四元数 + 相对参考保证"角度算得对"，
用 Qt 自绘 + 状态机保证"人看得懂、不会误信"，用测试 + 打包保证"能交付、能维护"。**
